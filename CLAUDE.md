# CLAUDE.md — правила работы в этом проекте

## Кто пользователь

Владелец проекта — **не программист**. Он оценивает результат глазами на сайте, а не по коду.

Поэтому:

- Общаться **по-русски**, короткими простыми фразами, без жаргона.
- Объяснять изменения в терминах результата («кнопка стала выше», «третий экран
  появляется позже»), а не в терминах кода.
- Не задавать технических вопросов, на которые можно ответить самому, прочитав
  код. Спрашивать только про вкус и содержание: тексты, цвета, порядок экранов,
  что именно должно происходить.
- Не показывать в ответе длинные куски кода. Если нужно показать — 3–5 строк.

## Главные правила работы

1. **Коммит в конце каждой законченной точки.** Не копить изменения. Точка = то,
   что можно описать одной фразой («добавил четвёртый экран с формой»).
2. **Перед коммитом всегда `npm run check`** (линтер + сборка). Сломанный код в
   `main` не коммитить никогда. Если работа не закончена и не собирается —
   отдельная ветка `wip/*`, а `main` остаётся рабочим.
3. **Работаем прямо в `main`.** Ветки — только под незаконченные эксперименты.
4. **После каждого коммита — строка в `CHANGELOG.md`** (по-русски, простым
   языком, что изменилось на сайте). Сообщение самого коммита — по-английски,
   как в существующей истории.
5. **`docs/` — первый источник контекста.** Перед тем как лезть в код, прочитать
   нужный файл в `docs/`. После изменений, которые меняют устройство проекта
   (новый экран, новый хук, новая папка ассетов), — обновить `docs/`. Косметику
   в документацию не тащить.
6. **Не добавлять новые библиотеки без разрешения.** Стек фиксирован: React,
   Vite, Tailwind, framer-motion, lucide-react.
7. **Проверять глазами.** Перед словом «готово» открыть превью (`preview_start`,
   конфиг уже есть в `.claude/launch.json`) и убедиться, что экран выглядит как
   надо. Не просить пользователя проверять вместо себя.
8. **Ничего не удалять и не переписывать историю git.** Никаких `push --force`,
   `reset --hard`, удаления файлов пользователя без явной просьбы.

## Экономия токенов

- **Никогда не читать и не листать**: `public/frames*`, `public/frames-turn*`
  (это 244 картинки), `media/`, `dist/`, `node_modules/`, `package-lock.json`.
  Если нужно узнать количество кадров — `ls public/frames | wc -l`.
- Начинать с `docs/`, а не со сплошного чтения `src/`. Файлы там маленькие и
  каждый описан в `docs/architecture.md`.
- Не пересказывать пользователю содержимое файлов и не объяснять код, если не
  просили.
- Один ответ = одна законченная мысль. Без длинных списков вариантов: выбрать
  лучший, сделать, коротко сказать что сделано.

## Как проверить проект

```bash
npm run check   # линтер + сборка, обязательно перед коммитом
npm run dev     # локальный сайт на http://localhost:5173
```

## Карта проекта (коротко)

| Что | Где |
| --- | --- |
| Сборка экранов, длина скролла | `src/App.jsx`, `src/components/stage.js` |
| Экраны | `Hero.jsx`, `About.jsx`, `Products.jsx` |
| Шапка, меню, промо-строка | `src/components/Header.jsx` |
| Фигура солдата (кадры + скролл) | `SoldierScrollFigure.jsx`, `useFrameSequence.js` |
| Тексты и картинки товаров | `src/data/products.js`, `public/products/` |
| Кадры анимации | `public/frames/`, `public/frames-turn/` |
| Генерация кадров из видео | `scripts/process-video.mjs` |

Подробности — в `docs/`.
