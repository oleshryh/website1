# Порядок работы

## Правило одной ветки

Вся работа идёт в ветке `main`. Никаких «сделаю в отдельной ветке, потом
объединим» — это лишний шаг, который нужен командам, а не одному человеку.

Исключение одно: если работа большая и на середине сайт не запускается, она
живёт в ветке `wip/что-то` и переезжает в `main` только рабочей.

Сейчас существует такая ветка: **`wip/screen-4-contact`** — незаконченный
четвёртый экран с формой контактов.

## Ритм: маленькие сохранения

Claude делает коммит (сохранение с описанием) в конце каждой законченной точки —
не раз в день и не в конце большой задачи. Из-за этого:

- всегда можно откатиться на шаг назад, а не терять всё;
- в `CHANGELOG.md` видно историю сайта человеческим языком;
- ни одно изменение не пропадёт.

Перед каждым коммитом обязательно запускается проверка:

```bash
npm run check
```

Это линтер плюс сборка. Если она не проходит — коммита в `main` не будет.

## Полезные команды

```bash
npm run dev
```
Запустить сайт локально: http://localhost:5173. Правки видны сразу, без
перезапуска.

```bash
npm run check
```
Проверить, что всё собирается. Запускать перед коммитом.

```bash
git log --oneline -10
```
Последние десять сохранений: слева код сохранения, справа описание.

```bash
git status --short
```
Что изменено и ещё не сохранено.

## Как откатиться, если что-то сломалось

Проще всего сказать Claude: «откати последнее изменение» или «верни как было
вчера». Вручную:

```bash
git restore .
```
Отменить все несохранённые правки — вернуться к последнему коммиту.

```bash
git revert HEAD
```
Отменить последний коммит **новым коммитом**. История сохраняется, ничего не
теряется. Это безопасный способ отката.

Опасные команды (`reset --hard`, `push --force`, удаление веток) в этом проекте
не используются.

## Отправка на GitHub

Репозиторий: https://github.com/oleshryh/website1

```bash
git push
```
Отправить сохранённое на GitHub. Локальные коммиты от этого не зависят — можно
работать и без пуша, а отправлять пачкой.

## Что делает Claude автоматически

1. Читает `docs/` перед тем, как менять код.
2. Делает изменение и проверяет его в браузере.
3. Запускает `npm run check`.
4. Делает коммит.
5. Добавляет строку в `CHANGELOG.md`.
6. Обновляет `docs/`, если поменялось устройство проекта.

Эти правила лежат в `CLAUDE.md` в корне и подхватываются в каждой новой сессии.
